## LoongCode 是什么

**LoongCode** 是一个基于 **Tauri 2 + React 19** 的跨平台桌面 **Agent IDE**，本质上是 **Claude Code、OpenAI Codex 等多套 Agent CLI 的统一图形化外壳**（后续将持续接入更多 CLI）。

它把原本只能在命令行里使用的 Agent 编程体验，搬进了一个真正的 IDE 式界面：

- 每一个「任务」对应一个独立的 AI 会话，可在 **Claude Code**、**OpenAI Codex** 等多套 CLI 之间按需切换（每个任务单独选择，模型 / 配置各记各的）；
- 应用以子进程方式拉起本机的 `claude` 或 `codex` CLI，通过流式 JSON 协议与其实时通信；
- 把事件流实时渲染成对话 UI，并在同一个窗口里集成终端、文件树、Git Review、命令 / 文件面板，以及各类设置。

> 💡 可以这样理解：**CLI 是引擎，LoongCode 是驾驶舱** —— 模型调用、代码执行、文件操作交给 CLI，多任务管理、历史还原、Git 集成等工作流增强交给 LoongCode；两者解耦运行、各自独立升级。

> ⚠️ **重要：LoongCode 自身不直接调用任何模型 API。** 所有模型交互都由它拉起的 CLI 子进程完成，API 密钥与模型配置也由 CLI 自行管理。因此在使用前，你需要先在本机准备好**必备依赖**：已安装并登录的 **Claude Code CLI** 与 **Git**；若想使用 **OpenAI Codex** 家族任务，再额外装上**可选依赖** **Codex CLI** 即可。
>
> 👉 没装也不必离开应用：LoongCode 内置**「依赖管理」**面板，可直接一键安装 Claude Code CLI、Git 与 Codex CLI（见下方「系统要求」与「🧩 依赖与一键安装」）；登录仍需你在装好后自行完成。

## ✨ 核心功能

### 会话与任务
- **多 CLI 支持（Claude / OpenAI Codex / OpenCode / Kimi / Qoder）** —— 任务可在 **Claude Code**、**OpenAI Codex**、**OpenCode**、**Kimi Code**、**Qoder** 等多个 CLI 家族之间按需切换（每个任务 / 草稿单独选择，配置各记各的）。Codex 与 OpenCode 任务均获得与 Claude 对齐的完整体验：对话**流式输出**、**交互式审批 + 优雅中断**、**历史还原**、**子智能体子卡片**、**会话分叉**，以及技能 / 插件 / MCP / 模型供应商的可视化管理；底层 Codex 经 `codex app-server`、OpenCode 经 `opencode serve` + SSE 事件流、新接入的 **Kimi Code** 经 **ACP 协议**（NDJSON 帧 + JSON-RPC）驱动，均以持久长连接保活，每任务 / 每目录一进程、懒启动、空闲回收。**OpenCode** 还支持**复用应用内模型供应商**（OpenAI 兼容，经 config 注入免手配 key）、**每任务思考深度 / 权限档位**、**worktree 会话迁移**，其工具卡与 Read 结果均归一为 Claude 风格。**Kimi Code** 在流式输出、思考过程、工具卡、审批应答、历史还原、子智能体对话、图片输入、斜杠命令面板等方面与 Claude 对齐，支持**会话中途切换模型 / 思考深度 / 权限档位**，内置**原生 Kimi OAuth 登录**（设备码流程自动拉起浏览器，登录 / 登出 / 状态 / 用量一应俱全）并提供 **K2.7 / K2.7 Highspeed / K3 / K3 [1m]** 模型档位，同样支持**复用应用内模型供应商**（经环境变量注入免手配 key，思考深度在外部供应商上同样生效），并将 **AskUserQuestion 渲染为 Claude 级选择卡**（点选项即可作答）。新接入的 **Qoder** 家族同样深度对齐——流式输出 / 思考过程 / 工具卡 / 审批应答 / 历史还原 / 子智能体对话 / 会话分叉 / 终端 TUI 模式均按 Claude 的方式工作——并自带 **Auto（智能路由）/ Ultimate / Performance / Efficient / Lite** 模型档位、专属的思考深度（低～最高）与权限档位选择器、依据 Qoder 用量比例推算的上下文用量条，以及**应用内原生 Qoder OAuth 登录**（设备码流程自动拉起浏览器，呈现在「模型供应商」页面）。**Codex 供应商现经 Responses API 直连**——路由由端点地址驱动，内置的中转开关已移除。新接入的三个家族以**实验功能**落地（受**设置 → 实验功能**门控，默认关闭）：**Hermes**——基于 ACP 协议的家族，设置面全面打通（模型供应商、经 `AGENTS.md` 的技能与记忆、插件、hermes 事件词表的 hooks、经 `config.yaml mcp_servers` 的 MCP、子代理委派配置卡、LSP 服务检测与逐个安装、带平台标签的工具凭证与 8 平台消息网关），每任务 `hermes_model` / provider / provider_model 落库持久化，**在线切模型保留历史**（会话模型存于 `state.db`，换模型后以新模型续接）、官方 `sessions export` 历史加载、依赖检测与 headless 一键安装；以及 **Pi**——基于游标的流式 JSONL 解析（消除逐行 drain 的 O(n²)）、文件级会话分叉（parentId DAG）、MCP 运行健康检测（stdio initialize 握手 / HTTP JSON-RPC）、子 Agent 运行态生命周期卡片、三档权限模式、包兼容升级检测（npm `dist-tags.latest`）、用量统计接入（受实验开关门控，camelCase usage 聚合，按 `message.id` / `promptId` 全局去重）；以及第 8 族 CLI **dsh（DeepSeek Harness）**（beta 门控）：由全局单例 `dsh web` 实例经 HTTP RPC + mux/host 双 WebSocket 驱动（指数退避重连封顶 30s，实例死亡自动重建，会话落盘重启恢复），插件清单与命令 / 功能门控状态、agent 预设扫描（系统 / 用户根）与预设 / 模型选择器（模型经 RPC 从应用自身供应商注入，免手配 key）、实时上下文注入卡与 ToolAsk 回执进历史、自有技能根扫描进斜杠命令面板 + 技能 / 记忆设置页、子 Agent 流式会话事件（对齐 Claude 的 SubAgentStream 渲染）、原生三档权限选择器（默认 full-access）、经 RPC fork 的就地重发（session repoint 改发）。
- **CLI 选择器只列已安装的 CLI** —— CLI 家族下拉框只列出本机实际存在的 CLI（安装检测为全局检测，启动时与安装完成后自动刷新）；当一个都未安装时，会显示红色提示并提供一键跳转到「依赖管理」面板的入口。
- **多工作区 / 多任务管理** —— 每个任务都是一个独立、可恢复的会话；任务列表按最近活动排序，在用的任务自动浮上来；选中任务时自动展开并聚焦其所在分组（工作区 / 置顶 / 时间线日期桶）。侧边栏工作区列表支持**拖拽排序**（顺序跨重启持久化；新建工作区自动置顶，重新打开应用也不会打乱你的排序）。侧边栏本身重组为**「全局 / 工作区 / 任务」三分区**（默认工作区承载非工作区任务），配 zcode 风格顶部操作区；全局 **Ctrl+K 搜索** popover 自侧边栏顶部浮出——默认按名称过滤，可勾选**深度搜索**与**包含归档**，并按勾选状态给出动态的空查询提示。
- **分屏对话（多分栏）** —— 主区可把对话切成多个分栏（左右 / 上下递归平铺、分割线可拖、可关闭塌缩、**拖分栏标题可停靠 / 交换重排，点击可内联重命名**），每个分栏是一个完整对话或新建草稿，可**跨工作区自由混排**；选中分栏时侧栏 / 文件 / 终端 / Git 自动跟随，布局会被记住，误关可 `Ctrl+Shift+T` 撤销。
- **终端 TUI 模式（分栏级）** —— 每个分栏都可以在图形对话与内嵌终端之间自由切换，终端里驱动的是**与原生交互式 CLI TUI 完全相同的会话**（Claude / Codex / OpenCode / Kimi / Qoder 均支持——Kimi 与其他家族一样续接其 ACP 会话）：终端从对话中断处精确续接，切回对话时终端内新产生的轮次也会被回读进聊天视图。终端实例统一池化保活，分栏的重新拆分 / 重新挂载都不会销毁它（不丢 scrollback、不闪黑屏）；会话被终端占用期间会出现一条持有态横幅（「进入终端 / 立即结束」），并禁用发送 / 分叉 / 回滚等入口，令两种模式互斥不冲突，静默无操作 10 秒后自动排水、结束持有。草稿任务**无需先发消息即可直接落入终端**——session-id 预绑定，聊天视图与 TUI 永远共享同一会话；全程不输入直接走开，未使用的绑定会被清理，终端轮次回读后，尚未命名的任务还会**依据首条用户消息自动命名**。
- **跨对话深度搜索** —— `Ctrl+Shift+F`（或搜索框入口）打开**覆盖全部任务对话历史的全文检索**（Claude、Codex、Kimi、Qoder 会话一视同仁，归档任务可按需纳入）：输入防抖、结果按任务分组、多关键词高亮并支持键盘导航，点击命中项直达原消息，并短暂高亮定位。
- **会话分享** —— 直接在对话内**就地勾选消息**（复选框选择模式，支持全选、实时计数与有效期设置），一键生成分享链接；勾选**「包含工具」**可让分享页同时携带工具调用片段（工具行随勾选解灰，ghost 单元锚定在首条工具行），文本与结构化工具负载均忠实还原；创建时还可选**设置密码保护**——成功弹窗会展示访问密码（支持单独复制），管理弹窗对受保护的分享标注锁形徽标，复制 / 打开操作改用完整链接。左下角徽标可打开**管理弹窗**，集中列出所有已分享内容并提供复制 / 打开 / 撤销 / 一键清空。链接由**可自托管的分享服务器**提供，在「设置 → 分享」独立分区中配置（服务器地址 + 发布密钥）。分享导出还会携带 **AskUserQuestion 问答记录**（tool_ask），交互式问答过程会完整呈现在分享页上。
- **任务归档** —— 不再活跃的任务可手动（下拉 / 右键，或在对话区空白处右键快速执行「归档并关闭」/「归档并新建」）或按最近活动时间自动归档，收纳进独立的「归档视图」，主列表更清爽；自动归档可在设置里开关与调阈值（小时 / 天 / 月），运行中 / 置顶任务受保护。
- **新建任务草稿态** —— 点「新建」先进入草稿，内联挑选工作区 / 模型 / Git 分支或 worktree，发送首条消息才正式创建任务（`Ctrl+N` 快捷新建，默认选上次用过的工作区）。
- **历史精确还原** —— 从 CLI 的原生会话记录（Claude 的 JSONL、Codex 的 rollout）加上应用侧的 sidecar 还原对话，连用户输入里的文件、命令、图片 chip 身份都能 1:1 复原。冷打开历史任务时，对话区在历史水合期间展示**加载过渡动画**。
- **按需导入历史会话** —— 把任意工作区的过往 CLI 会话按需导入为任务：扫描全部五个 CLI 家族（Claude / Codex / OpenCode / Kimi / Qoder）的会话，支持搜索、重复标记与一键批量建任务——旧的终端会话可以在 LoongCode 里直接重新打开、继续对话。
- **会话分叉 / 优雅中断 / 重跑** —— 从任意历史节点 fork 出新会话；点「停止」等价于按 ESC 优雅中断，保留已生成内容、可继续对话。
- **编辑历史用户消息**，并从该点继续。
- **子 Agent 子对话** —— 子 Agent 的对话被路由进独立的折叠卡片，采用与主线相同的气泡 / 纯文本视觉语言呈现（头卡以被委派任务的主题命名，展开后先是一条指令气泡，随后是完整的逐轮消息流），主线清晰不打架。通过 `SendMessage` 再次给子 Agent 发消息时会原地续接其实时流——哪怕该子 Agent 此前已经退出，卡片也会翻回「运行中」——协调者注入的后续指令以指令气泡形式内联渲染；`SendMessage` 工具卡还新增**跳转到目标入口**，点击可滚动到目标子 Agent 并短暂高亮，并沿嵌套的上级链路自动展开沿途所有折叠卡片（一旦向上滚动离开底部，会出现悬浮的**回到最新**按钮）。
- **后台任务活动指示与查看** —— 以 `run_in_background` 跑起的后台命令、异步子 Agent、服务进程与**动态工作流**等，全程实时可见、绝不卡住「运行中」：任务行与**各分栏自己的输入工具栏**（作用域限定在该分栏所属的任务，不再是单一的全局标题栏指示）会用 **⚡N 指示灯** 汇总数量，完成 / 失败以高亮点呈现读未读、且可逐个清除（不弹窗、不出声）；点开**分组浮层**速览所有后台项（工作流条目带专属图标与种类提示）；发起后台任务的工具卡会在底部追加**后台状态条**，并新增**「查看输出」入口——哪怕任务仍在运行也能点开**（后台子 Agent 可就地展开看子对话，含嵌套子 Agent 实时渲染）；命令 / 服务类任务还可在右侧打开**可关闭的实时日志视图**，任务运行期间会持续追加新输出。
- **动态工作流可视化（Claude / Qoder，非阻塞）** —— 发现并触发 Claude Code 动态工作流（用户 / 项目 `.claude/workflows/*.js`）与 **Qoder 工作流**（经 Qoder 的 `transcriptDir` 读盘路径重建，附实时富卡——由工具结果、快照轮询与解封（envelope-unpacked）结果合成的「已开始」卡），运行进度渲染成富进度卡：阶段分组（运行中自动展开 / 空闲自动收缩）、子智能体下钻查看 transcript、用量与结果一目了然，应用重启后还能从磁盘重建卡片。工作流**全程后台非阻塞运行**：执行期间输入框不锁定、可继续对话，并入后台任务体系（⚡ 指示灯 / 未读灯 / 侧栏计时 / 后台活动浮层同步覆盖），长跑工作流不会被空闲回收误杀，进程异常退出或手动终止也会如实标记失败。
- **定时执行消息** —— 给任务设定时发送：支持指定时间 / 间隔 / 每日 / Cron 四种模式，内置免依赖的日期时间选择器，草稿态任务也能预约；定时状态用紫色指示灯呈现，可在全局总览里集中查看与管理。
- **任务看板（依赖感知自动派发）** —— 五列看板（Planning / Pending / In Progress / Review / Done），卡片即任务：dnd-kit 跨列拖拽与列内排序（带移动合法性校验）、工具栏防抖搜索 / 工作区标签筛选 / 并发上限设置。每张卡片携带**完整 CLI 配置快照**（复用 ModelSelector 的模型选择器，覆盖全部 CLI 家族）、**依赖拓扑图**（dagre 分层布局，只读 SVG，点节点开详情）、评论区（排队 / 已送达标记、分裂的「发送并移动」/「仅发送」按钮）、依赖编辑区（搜索添加 / chip 跳转 / 移除，删除二次确认），以及**内嵌对话区**（最近消息、待答权限提问可就地作答、跳分栏）。打开卡片会 **reconcile 其 worktree**（释放的卡片自动回退主分支），选中卡片贯通终端 / 资源管理器 / git 面板的 worktree 根目录，对话区按轮次分组、评论点击跳转定位并活更新（乐观评论气泡、run 结束重载），**依赖感知派发器**在并发空位出现时按 15 秒 tick 拾取 pending 卡（依赖全部 done），组装 prompt 建任务——in_progress 由系统托管，崩溃残留自动落入 Review。
- **移动端支持（微信 ClawBot / 飞书 Lark）** —— 绑定微信官方 ClawBot 或飞书机器人后，用手机即可远程新建 / 驱动任务、接收 AI 回复，连交互式提问（AskUserQuestion）也能回数字作答。飞书渠道为**原生 Rust 长连接**实现：扫码建应用绑定、私聊全转发 / 群里 @ 机器人触发、连接健康指示灯（绿 / 黄 / 灰），网络波动自动重连且不丢凭据。
- **PC 远程桥接（移动端伴侣）** —— 用手机扫码与桌面配对后，经**加密中转**与桌面建立可靠双向连接，把桌面任务搬到手机上远程驱动：实时收发对话消息、**历史保真回放**（用户消息里的富文本 / 图片切回手机端依旧可见、每条 event 附全局稳定序号）、按任务路由、优雅中断，输入框同样支持 **/命令 · @文件 · 图片**等富输入；打开任务即拉取**权威状态快照**与归档标记，运行中 / 已归档一目了然。桌面**四件套配置（模型 / 推理强度 / 权限 / CLI）双向同步**——本地改动回推 App、远程改动落库桌面，**OpenCode 任务的模型 / 供应商 / 思考深度 / 权限档位等配置同样可在手机端回显与修改**，斜杠命令 / 技能列表也覆盖 OpenCode，且**严格跟随任务所选 CLI**（草稿态切换 CLI 后，命令 / 技能 / 工作流列表随之切换，不再固定按 Claude 列出）；交互式提问与权限请求**单点作答、双向同步**，桌面端作答后已答态实时回传手机，两端绝不重复打扰，**待答的权限请求在重开任务时依旧可继续作答**（停止 / 中断路径同步清理，不留幽灵审批卡）。**后台任务与动态工作流同样远程可见**——手机端实时收到后台任务状态、后台子 Agent 的内部对话在活跃回合内实时流出，应用冷启动时从磁盘重建的工作流运行随打开任务回填、工作流子智能体的 transcript 远程可查。底层为**原生 Rust** 实现：ECDH 配对 + 端到端加密、断线自动重连重发不丢包、应用层心跳保活与假在线检测、**息屏 / 系统休眠保活**（借助电源管理断言让连接在息屏期间保持存活，并通过系统时钟跳变侦测唤醒，让桥接与机器人在数秒内重连），设备解绑即时生效并向已解绑的 App 明确回执。

- **群聊 / 多成员协作** —— 从成员库组建一支 AI Agent 团队（Claude / Codex / OpenCode / Kimi / Qoder 成员按各自家族佩戴专属模型、思考深度与图标），在同一个共享对话里畅聊：编排器把轮次串成链（链内串行、链间并行、单成员全局串行——派生的接力链会对已排队的成员去重，且**每轮编排都会注入成员名册**，@ 必须匹配精确全名），支持**按成员细粒度紧急停止**或**整组停止**（墓碑标记吞掉迟到的旧事件），并跨重启全量持久化（三表结构、隐藏任务豁免、二层换脑恢复）。**权限下拉框按各成员的 CLI 家族自适应**（以家族原生值字符串存储——codex / opencode / kimi 权限不再被丢弃），实时事件流经 40ms 窗口合并以吸收多成员并发洪峰，同时以常驻的创建入口兜底，保证任何状态下都恰好存在一个创建入口。消息渲染为流式分段会话——思考进独立字段（正文无思考噪音）、气泡按成员折叠并支持工具组批量展开、气泡内 @成员 chip 内联渲染、各分段按到达顺序交错呈现。Composer 集成两段式 @ 面板（成员 / @全体）。全局的**设置 → 实验功能**分区提供群聊开关（默认关闭）——该分区同时收纳 **Hermes** 与 **Pi** 两个实验 CLI 家族（全部默认关闭；Hermes 与 Pi 全关时，依赖管理面板会隐藏其折叠分组）。

### 对话体验
- **富文本消息气泡** —— Markdown 渲染、表格、代码语法高亮、Markdown 预览。
- **Markdown 本地链接与图片渲染** —— AI 消息里的本地文件路径渲染为内联**文件 chip**（内部相对引用按任务工作区解析；外部绝对路径经专用 `stat_path` 命令做存在性校验，缺失时降级为无操作链接；Codex 风格的 `path:line:col` 链接形式会剥掉行 / 列后缀、变成普通文件 chip）。本地与远程图片直接在气泡内渲染——点击可放大进灯箱、右键可复制源图，对话右键菜单还按目标类型提供**复制图片 / 打开外部文件**入口。非 web、非 `mailto` / `tel` 的链接一律为 no-op——点击被彻底拦截，终于消除了本地文件链接曾经触发的整页重载刷新。**Mermaid 图表就地渲染**——AI 消息内的 `mermaid` 围栏代码块变成可点击放大进灯箱的活图表，支持 PNG/SVG 导出。
- **工具调用时间线卡片** —— Read / Write / Edit 的 diff、WebSearch 结果等聚合成连续的时间线卡片（连续调用共享左缘线、可逐行展开详情），一目了然又不占地方。Codex 的工具调用同样享受语义化处理：`apply_patch` 会展开为带行号的写入 / 编辑 / 删除卡片，只读 shell 命令经启发式识别后渲染成读取卡（覆盖 PowerShell / cmd / bash 包装形式），shell 命令卡还带运行器徽标（python / node 等）——同时始终保留原始工具名可见。
- **交互式提问（AskUserQuestion）** —— 在 UI 里直接点选选项；悬停选项可在分屏中预览详情（点击可锁定预览，窄面板下降级为堆叠布局），支持「其他」自定义输入，以及**「先讨论」入口**（作答前可与 AI 展开自由对话，对齐官方的 Chat-about-this 流程）。待审批 / 待选择卡片现在**可跨应用重启存活**（冷启动快照）——重开任务可继续作答，不留幽灵卡。
- **AI 消息工具栏**、对话内链接用系统浏览器打开、任务状态与未读指示。

### 输入（Composer）
- **斜杠命令面板**（`/command`，内置**按 CLI 家族分流的目录**——20 条 Claude 精选命令 + 专属的 22 条 Qoder 命令集，说明文案跟随界面语言，不同家族的同名命令互不串扰；面板还会收录**工作区级技能**并标注正确的作用域徽标，插件装卸瞬间即时刷新）与 **@ 文件提及面板**、内联文件 chip。
- **图片输入**、**每任务独立草稿**、**模型 / 推理强度选择器**（Claude 登录内置 **Fable** / Opus / Sonnet / Haiku 档位；Codex 登录内置 **Codex OAuth** 原生档位与 minimal～xhigh 推理强度；OpenCode 复用应用内 **OpenAI 兼容供应商** 并可为每个任务选择思考深度；Kimi 登录内置经 Kimi OAuth 提供的 **K2.7 / K2.7 Highspeed / K3 / K3 [1m]** 原生档位，同样可复用应用内供应商；Qoder 自带 **Auto / Ultimate / Performance / Efficient / Lite** 档位与专属推理强度选择器；模型下拉按当前 CLI 家族过滤）、可自定义的输入工具栏。
- **IME 安全的 chips 与可放大的图片 chip** —— 紧贴 chip **输入中日韩文字**不再打断 IME 组词或吞字符：零宽渲染锚点 + 光标钳制让光标始终停留在每个 chip 的安全侧，复制文本也不会带走那个零宽字符。图片 chip 渲染为方形缩略图，**点击可放大**，删除 ✕ 也不再被圆角容器裁切。
- **语音交互（实验功能，默认关闭）** —— 草稿分栏可切入**语音模式**（保留居中布局；发送首条语音消息时才正式创建任务）。说出唤醒词**「小码」**（默认，采用与常见 IME 相同的模糊拼音容错集做模糊匹配）即有声唤醒应答；语音输入经设备端 STT（whisper，自动语言检测）转写，按普通消息路由——包括用语音应答选择 / 审批卡与多选问题。回复由本地 TTS 引擎朗读（Kokoro / Melo / Matcha 中文音色，外加 fanchen-C / aishell3 纯中文音色，ONNX 多线程推理），带流式断句（自动跳过代码块与表格）、回声过滤（TTS 永远不会回灌进麦克风）、回复与审批卡的播报阅读，以及完成条上的重播按钮。语音消息渲染为**音频气泡（AudioChip）**，右键菜单可展开转写文本、复制内容或隐藏文本。全部在专属的**设置 → 语音**页面配置（唤醒词 / 静默超时 / 模型下载 / 音色与语速 / 总开关），并受全局**设置 → 实验功能**开关门控。

### 集成开发工具
- **集成终端** —— 基于 xterm.js + PTY 的真实终端；终端日志里的链接可点击（左键在内嵌浏览器打开、右键调系统浏览器或复制地址）。右侧文件面板同样集成**终端 tab**（常驻渲染、面板开合门控，Windows Terminal 风格标签栏——等比压缩、溢出箭头、浮动选中态）；侧栏 / 终端面板开合带 **200ms 滑动动画**。
- **文件树侧栏 + 侧边文件面板 + Monaco 编辑器** —— 浏览、查看代码与 Diff。
- **打开文件外部修改实时同步** —— 打开的文件 tab 通过常驻的父目录 watcher 持续监听磁盘（路径过滤 + 去抖聚合）：文件在应用外被修改或删除时，tab 立即响应——弹出**外部修改冲突对话框**（加载外部版本 / 保留我的修改），Monaco 经**最小公共前后缀编辑**重载（保留光标与撤销栈），外部删除的文件显示**删除线 tab 标记**并支持 `Ctrl+S` 一键重建（全局 `Ctrl+S` 兜底同样覆盖侧边面板预览文件，并透传 worktree 路径）。
- **富文件预览** —— 侧边面板原生渲染 10+ 种非代码文件：Office 文档（Word / PowerPoint / Excel）与 PDF、CSV/JSONL/Parquet/SQLite 呈现为可排序表格、图片（含 AVIF/ICO）与音视频（经 asset 协议流式播放）、压缩包内容（zip/jar/tar/gz，免解压即可浏览）、面向任意二进制文件的 Hex 查看器、字体样张、SVG（渲染 / 源码切换），以及 Jupyter Notebook。**Excel（.xlsx）支持原地编辑单元格**（双击单元格进入编辑，公式单元格受保护，未保存的改动会被标记），预览中的任意文件都可**用系统默认程序打开**。**HTML/HTM 文件获得内嵌实时预览**——iframe `srcdoc` + base 注入，相对资源按文件所在目录解析，经递归 asset 目录放行名单提供服务——并加入文本双模式家族，每个 tab 带**编辑 / 预览切换**（编辑为默认）。预览还升级出 **UI 编辑模式**：注入 bridge 脚本（默认休眠）让渲染页面内即可 hover / 选中 / 拖动 / 行内编辑，悬浮配置面板分内容 / 样式 / 属性 / HTML 四个分区，eid 派生的补丁引擎把编辑**免刷新**直接写回源码——由防抖提交流水线支撑，支持撤销重做。独立 **`.mmd` / `.mermaid` 文件**作为一等文档打开：整文件图表渲染、语法高亮、PNG/SVG 导出。
- **文件树多选与文件操作** —— 单击选中 / 拖拽框选，复制 / 剪切 / 粘贴（接入系统文件剪贴板，与资源管理器互通）、新建 / 重命名 / 删除，支持 `Del` 与 `Ctrl+C/X/V` 快捷键。
- **Git 工作流** —— 分支切换、变更 Review 面板、提交菜单（含 ✨ 一键生成提交消息）、worktree 自动检测与跟随。**Git 图谱对话框**可视化提交历史（分页 `git log --graph` 扫描器，90% 视口滚动分页）——从分支弹层进入，点击任意行展开提交详情面板。草稿任务获得**「新建 Worktree」选项**：先创建 worktree（自动以 `wt-` 前缀命名，并注册进 `.git/info/exclude`，绝不污染仓库），再把任务绑定到它；文件 tab 按物理绝对路径去重、面包屑显示真实 worktree 路径（`.codex/worktrees/<n>/…`）、文件 chip 按任务自身 worktree 根解析相对路径。
- **内嵌浏览器面板** —— 在右侧面板直接打开网页，支持多标签、跨任务共享，查文档 / 预览页面无需离开应用。
- **在文件资源管理器中打开**当前工作区。
- **「打开方式」（OS 文件关联）** —— LoongCode 注册为系统「打开方式」候选（Windows NSIS 安装器、macOS `public.data` 文档类型）；从系统打开的文件进入文件面板，应用已运行时会经 single-instance 转发（转发参数列表会过滤掉应用自身可执行文件）。

### 配置与扩展
- **Skills（技能）/ MCP 服务器 / Plugins（插件）/ 子智能体（Subagents）** 的可视化管理 —— 覆盖全部五个 CLI 家族 **Claude / Codex / OpenCode / Kimi / Qoder**（OpenCode 天生共享 Claude 技能根、经托管 `opencode.json` 管理 MCP 与技能 / 子智能体 / 斜杠命令的启停；Kimi 拥有独立的技能扫描、用户级与工作区级 MCP `mcp.json` 增删改查（改动自动重启子进程）、**从 marketplace 安装插件**（装卸启停即时生效），子智能体经 `AGENTS.md` 管理；**Qoder** 在技能 / 插件 / 子智能体 / MCP 各面板都有专属 tab，全部路由到其 `~/.qoder` 根目录，绝不混进 Claude 的配置）；子智能体支持**用户 / 项目 / 插件**三作用域的查看、新建、编辑、删除与启停（插件提供者只读）。
- **记忆管理** —— 专属的「设置 → 记忆」面板，无需离开应用即可列出、预览、编辑、新建、删除各 CLI 的持久化指令文件：Claude 的 `CLAUDE.md`、Codex / OpenCode / Kimi / Qoder 的 `AGENTS.md`（均含全局与项目级两个层级），以及 Claude 的**自动记忆（auto-memory）**主题文件，以可搜索、可自由命名的集合形式呈现。
- **Hooks（钩子）设置** —— 在 UI 里直接查看、新增、编辑、删除 Claude、Codex、Kimi 与 Qoder 的生命周期钩子（工具调用前后、会话开始 / 结束等）—— 覆盖 Claude 与 Qoder 的用户 / 项目共享 / 项目本地三层 `settings.json`（Qoder 在其自己的 `.qoder` 根下）以及 Codex / Kimi 的 `config.toml`，已知字段提供结构化表单（无法识别的字段回退为原始文本），并附带插件或托管策略贡献的钩子的只读汇总视图。
- **Model Providers（模型供应商）** 配置，自由切换后端 —— 常见模型内置**上下文窗口出厂默认值**，新增模型时输入框占位符直接给出推荐值（留空也有合理默认）。每个供应商可独立设置**网络代理**（跟随系统 / 自定义 / 关闭），由 CLI 登录支撑的供应商（例如 Codex OAuth 中转，或 **Qoder OAuth** 行——会在浏览器中打开设备码页面）还提供应用内**登录 / 状态 / 登出**流程，登录命令可编辑，并支持一键刷新模型目录。Claude 家族供应商还可选择呈现的**鉴权头**（`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`），以对应环境变量注入 CLI 子进程。
- **依赖管理 + 运行时版本管理** —— 依赖列表从静态目录即时渲染（每项的安装状态在后台懒检测），按必须 / 可选分层呈现；**必备依赖 Claude Code CLI 与 Git 支持应用内一键安装**（Windows 直接装好，macOS 的 Git 走系统 Xcode 命令行工具引导），**OpenAI Codex、OpenCode 与 Qoder CLI 亦可应用内一键安装 / 更新**（至少装其一即可）；对 `uv` / `pnpm`（及 `bun`）可列出 / 安装 / 卸载 / 切换多版本，并支持一键兜底安装。
- **代理设置** —— 按模型供应商单独配置（见上文），不再是单一全局开关；仅支持 http / https（不支持 SOCKS）。依赖下载（CLI 安装器、`uv` / `pnpm` / `bun`）默认跟随系统代理，也可按依赖单独覆盖。
- **环境变量设置** —— 为 CLI 子进程（Claude / Codex）注入自定义环境变量（改动自动触发子进程重启）。
- **用量统计（Usage）** —— 直观查看消耗；通过 Claude 或 Codex OAuth 登录后，侧边栏与该供应商的登录卡片上会显示实时用量徽标（会话 / 每周百分比，每 5 分钟刷新一次），Codex 用量需通过实验性开关手动开启。统计现已横跨**全部四个 CLI 家族——Claude / Codex / Kimi / Qoder**，可切换每个 CLI 的维度，图表与模型表格动态配色（12 种精选色 + 黄金角溢出，随主题调校），并**拆分缓存 token**：模型表格新增总计 / 输入 / 输出 / 缓存四列双语标签，总 token 卡显示缓存命中率副行、逐模型命中率跟随缓存命中、排名按总计排序（中转 / 中间商会话也计入 Codex 用量）。悬停**热力图单元格（每日）**或**趋势点（按模型）**可查看输入 / 输出 / 缓存命中明细，而总 token 卡、热力图与每日趋势都**计入缓存读取**，让每一项数字与模型表格的列保持一致。**账号用量全局开关**（设置 → 通用）可一键关闭整个功能：侧边栏徽标彻底隐藏、后台轮询与手动刷新一并静默、供应商登录卡的用量子块转为禁用提示——即时生效，无需重启。macOS 上，后台检查用量 / OAuth 登录状态也不再触发系统「访问其他 App 数据」的权限弹窗。

### 桌面体验
- **全应用自定义右键菜单** —— 对话区、预览、文件树、任务行、侧边栏空白处都有贴合场景的右键菜单，替换系统默认菜单。
- **后台任务栏提醒** —— 窗口不在前台（含最小化）时，AI 完成 / 失败 / 弹出确认请求会像 QQ / 微信那样闪烁任务栏图标。
- **新建任务记住上次配置** —— 新建任务 / 技能自动继承上一次使用的模型供应商与参数。
- **原生窗口装饰（macOS）** —— macOS 采用系统原生 Overlay 标题栏与三键（红黄绿）按钮，侧边栏头部改为**两行布局，logo / 字标独立一行、置于三键下方**，并为其预留安全区，同时支持刘海屏全屏安全区；Windows 维持无边框定制窗口。
- **主题化与配色一致性（宣纸墨金）** —— 全新「宣纸墨金」视觉语言：三套精心调校的主题（深色 / 浅色 / 护眼黛青），暖调宣纸底 + 墨色文字 + 金印点睛，内容性标题采用思源宋体衬线、深色主题辅以背景淡金光晕；对话区、输入区（纸面浮盒 + 圆形金印发送钮）、任务行（金书签状态谱）、设置页（纸面卡分组）、文件面板 / 终端 / Monaco（gruvbox ANSI16）全域一致换肤。全应用配色建立在统一的主题 token 地基之上（角色 / 分类色盘 / 语义 token，深浅自适应），diff、子 Agent、Review、用量警戒、机器人连接灯、工作流状态、模型色盘、标签族等场景全部接入 token 而非写死颜色，跨主题观感一致，默认跟随系统深浅。
- **全新应用图标「衔尾圆环龙」** —— 玄墨金圆角方章徽章：衔尾成环的小龙落在玄墨底上、金鳞点睛；应用内侧边栏 logo 按三主题（深色 / 浅色 / 护眼黛青）跟随切换、各显专属配色，护眼主题字标采用黛青同色。
- **界面语言（中 / 英）** —— 整个图形界面支持中英文切换，默认跟随系统语言、识别不到时回退英语，可在「设置 → 常规」随时切换；AI 对话内容不受影响。
- **中 / 英文安装界面**，安装时可选语言。
- **关于页面** —— 专属的「设置 → 关于」页面：应用 / 版本信息、六态更新检查行、完整的许可协议与隐私政策文本页（中 / 英文，跟随界面语言）、赞助小节（微信 / 支付宝二维码），以及带官方仓库链接的联系方式行（可复制邮箱）。
- **内置自动更新** —— 启动后静默检查并提示升级。
- **新手引导（Onboarding Tour）** —— 第一次使用不迷路。

| 必备依赖 | Windows | macOS |

## ❓ 常见问题

**Q：本机还没装 Claude Code CLI 或 Git，必须手动装吗？**
A：不用。打开 LoongCode 后进入 **设置 →「依赖管理」**，在「必须依赖」里点「安装」即可。Windows 上 Claude Code CLI 与 Git 都能直接装好；macOS 上 Git 会调起系统 Xcode 命令行工具安装。装好 Claude Code CLI 后记得完成登录。

**Q：装好后无法对话 / 没有任何模型响应？**
A：LoongCode 不自带模型能力，它依赖本机的 CLI 工具。请确认对应 CLI 已安装、在 PATH 中并已完成登录：Claude 任务需要 `claude`，Codex 任务需要 `codex`。

**Q：公司网络需要代理怎么办？**
A：在应用设置中配置 http / https 代理。注意被拉起的 CLI 仅支持 http/https，不支持 SOCKS。

**Q：更新检查不到新版本？**
A：自动更新依赖本仓库 Releases 的 `latest.json`，请确认网络可访问 GitHub。
